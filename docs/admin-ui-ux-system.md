# Admin Base UI/UX 页面与表格规范

## 1. 目标

Admin Base 的界面服务于高频、重复、需要比较和追踪的后台工作。页面应保持安静、紧凑、可扫描，优先保证数据身份、状态、操作和上下文连续性，不使用营销式大标题或装饰性卡片堆叠。

本规范覆盖当前 `route-manifest` 中的 26 个后台页面。新增模块必须先判断页面属于哪种工作流，再选择布局和表格策略，不能直接复制一张无限宽、无限高的通用表格。

## 2. 页面层级

普通内容页使用标题、说明和页面级动作。以列表为主的页面不再重复展示独立大标题，统一由 `AdminDataTable` 承载完整工作区：

1. 表格身份区：业务名称和当前结果总数。
2. 表格控制区：筛选开关、每页数量、刷新、行间距、边框和列设置，固定在工作区右上侧。
3. 查询区：只放影响当前数据集合的筛选；支持收起，筛选值和排序继续写入 URL。
4. 数据命令区：快捷状态、业务动作、关键字搜索和创建按钮。
5. 主数据区：固定表头、局部滚动的表体和固定关键列。
6. 数据底栏：分页和总数；必须和数据框架连在一起。

列表页仍通过 `PageScaffold` 提供语义标题，但使用 `hideHeader` 隐藏重复的可视页面标题。详情页、设置页、Dashboard、Chat、Playground 和需要页面级解释的工作台继续保留页面标题区。

页面区段使用无边框布局或完整工作区。卡片只用于需要明确边界的数据工具、重复指标、Modal、Drawer 和独立工作面板；不在卡片内部继续嵌套装饰性卡片。

### 2.1 工作区高度与滚动

- Shell 统一扣除顶部导航、访问页签、页脚和页面内边距，业务页不重复编写 `calc(100vh - ...)`。
- `AdminPageWorkspace -> PageScaffold -> admin-page-content` 必须保持连续的 `flex: 1` 和 `min-height: 0` 高度链。
- 26 个后台路由都必须通过 `PageScaffold` 承载；`tests/ui/admin-workspace-contract.test.ts` 负责阻止新页面绕过该约束。
- 页面标题区、查询区和工具区按内容高度排列；主表格、Tabs、树、会话、双栏和发布工作面填满剩余高度。
- 桌面端不使用页面整体滚动承载长表格。表体、树、Tab 面板、聊天消息、模型输出和代码差异在各自工作区内部滚动。
- 空数据、加载、错误和权限不足状态不能让工作面收缩；表格框架、Card 底边界和分页位置保持稳定。
- 窄屏允许页面恢复自然高度和纵向滚动，不能为了桌面端撑满而裁掉表单或操作按钮。

## 3. 表格工作流

### 3.1 普通 CRUD 表格

- 适用：用户、存储、邮件、OAuth、SMS、AI Provider、AI 模型、短信模板、通知公告。
- 数据框架必须有完整的上、下、左、右边界。
- 默认使用共享的聚焦式工作区头部，不在表格上方再堆叠页面大标题和独立搜索卡片。
- 表格左上角显示业务名称和总数；筛选、每页数量、刷新、行间距、边框、列设置位于右上角。
- 创建、关键字搜索和自定义业务动作位于数据命令区右侧；页面不得各自复制一套工具栏。
- 业务快捷筛选通过 `quickFilters` 声明并复用 URL 查询状态，不在页面本地维护第二套筛选状态。
- 分页位于数据框架底部，使用顶部分隔线，不悬浮在页面空白中。
- 存在横向滚动时，固定左侧 ID + 主要身份列，固定右侧操作列。
- 主要身份列包括用户名、资源名称、模型名称、公告标题等。
- 状态、类型、默认标记使用紧凑标签，不用大色块填充整行。
- 默认单行高度约 44px；用户可切换密度，但页面结构不能随密度跳动。
- ID、优先级/顺序和 `createdAt`、`updatedAt` 等时间列统一提供服务端升序/降序；不能只重排当前页。
- 排序状态写入 URL 的 `sort=<field>.<asc|desc>`，搜索和分页保留当前排序，重置操作才清除排序。
- 普通列表使用 ID 作为稳定的第二排序键，避免相同时间或优先级在翻页时抖动。
- 树形菜单、组织树和 Agent Step 时间线保留业务层级或执行时序，不机械套用普通 CRUD 排序。

### 3.2 长日志与会话表格

- 适用：操作日志、登录日志、在线用户。
- 每页默认 20 条，数据体限定在当前可视工作区内滚动。
- 表头固定在表格滚动容器顶部，分页固定为表格底栏。
- 左侧固定结果/模块/用户等定位字段，右侧固定查看或下线操作。
- User-Agent、请求路径、Request ID 等长文本使用省略、复制或详情查看，不撑高行。

### 3.3 主从工作台表格

- 适用：角色、部门、字典、配置、文件。
- 主表和详情面板必须同时保留上下文，局部表格使用有限高度，不能把右侧详情推到几屏之外。
- 选择行是导航行为时要有清晰选中态；编辑仍使用明确按钮，不能混淆行选择和写操作。
- 面板内分页属于面板，不属于整个页面。

### 3.4 权限树表格

- 适用：菜单权限。
- 保留树层级缩进和展开控制。
- 使用有限高度和固定表头，避免 100+ 行把页面拉成长页。
- 操作列固定右侧；名称、路由和权限码保持稳定宽度。
- 横向滚动条、底部边界和表格必须属于同一个视觉框架。

### 3.5 Drawer、Modal 和详情表格

- 适用：公告阅读明细、回收站、角色用户、部门用户、个人登录记录、OAuth 绑定。
- 表格在 Drawer/Modal 内部滚动，不使用页面级 sticky 偏移。
- 操作列固定右侧；内容高度超过约 8-10 行时启用内部固定表头。
- Modal/Drawer 的底部动作区与数据表格分开，避免误以为分页按钮是提交按钮。

### 3.6 专用数据画布

- 适用：文件表格预览、AI Chat、AI Playground、AI Agent 运行详情。
- 不强制套用普通 CRUD 表格规则。
- 聊天、预览和运行步骤优先保证连续阅读、输入位置和上下文，不使用全页固定表格头。

## 5. 响应式与主题

- 桌面端优先保证横向比较；小屏允许横向滚动，固定列总宽不能占满内容区。
- 页面标题、工具栏和筛选项可以换行，但按钮和文字不能重叠。
- 不能按视口宽度缩放字体；紧凑表格正文保持 13-14px。
- 暗色主题必须使用语义变量：`--admin-bg`、`--admin-surface`、`--admin-surface-muted`、`--admin-border`、`--admin-border-soft`、`--admin-text`、`--admin-muted`。
- 固定列背景必须跟随当前主题，不能出现白色固定列盖在暗色表格上。
- 只有文件、图片、视频、Office 和代码预览可以保留内容自身的专用画布颜色。

## 6. 新页面验收清单

- 页面属于哪一种工作流已经明确。
- 标题、查询、工具、数据、分页层级清楚。
- 主要身份字段无需滚动即可定位，或已按规则固定。
- 横向滚动时操作列可见且不遮挡内容。
- 普通列表的 ID、优先级和时间列可执行服务端升降序，刷新和翻页后排序不丢失。
- 20 条以上长表格不会生成数千像素高的页面。
- 表头、最后一行、横向滚动条和分页区都有完整边界。
- 空状态、加载状态、错误状态不会改变整体布局宽高。
- Drawer/Modal 内的表格在容器内部滚动。
- 明暗主题下固定列、表头、分页和边框颜色一致。
- 1280px 桌面和窄屏下不存在文字、按钮和表格重叠。
