# Admin Base Product Design UX/UI Redesign Plan

## Brief

用 Product Design 方式把现有 Ant Design Admin 收敛成更适合起手式后台的运营工作台：

- 保持现有技术栈、路由、权限和业务交互。
- 不做营销式首页，不引入新的视觉资产依赖。
- 优先提升高频管理体验：首屏请求、表格扫描、筛选、弹层表单、空状态和移动端可用性。

## Branch Boundary

- `codex/admin-base-migration-plan` 已包含基础能力完成和 React Query 请求层试点。
- `codex/product-design-admin-ux-redesign` 从该基础提交切出，只承载 Product Design UI/UX 调整。
- 本分支不再扩大请求层重构范围；后续页面的 React Query 迁移回到基础/优化分支推进。

## First Pass Scope

继承的基础能力：

- React Query 接管 `AdminDataTable` 的列表请求、缓存、刷新和增删改失效。
- 用户页的角色、部门选项改成表单/下拉触发式懒加载。
- 用户列表接口返回 `roleNames`，避免首屏为了展示角色名称额外请求角色选项。

本分支已落地：

- 全局 shell、页面标题、卡片、搜索区、表格、弹层和空状态统一视觉密度。
- 登录页移动端约束和品牌文案收敛到 `Admin Base`。
- 用户页文案从“管理员列表”收敛为“用户列表”，避免菜单和页面语义不一致。
- 菜单权限编辑 Drawer 调整宽度、左右间距、标题和底部操作区，提升长表单编辑体验。
- 系统配置中的文件相关分组统一称为“文件策略”；实际存储通道由“存储配置”维护，避免“文件配置/存储配置”歧义。

## Design Rules

- 表格页以数据扫描为主，页面标题短、描述克制、操作区靠近表格。
- 搜索区使用浅背景带边界的筛选带，避免与数据表混在一起。
- 卡片只用于真实容器、侧栏面板、数据卡片和弹层，不嵌套装饰卡片。
- Modal/Drawer 标题、分割线、底部操作保持一致。
- 服务端数据缓存用 React Query；登录态、权限、菜单、布局偏好继续用 Zustand。
- URL 继续承载表格搜索、分页和排序状态。

## Later Product Design Migration Order

1. 角色页：权限树、已分配用户和保存反馈统一为右侧工作区模式。
2. 部门页：部门树、部门信息和成员列表的选中态、空态、加载态统一。
3. 配置页：配置分组、配置项编辑和文件策略说明强化层级关系。
4. 文件页：文件夹、文件列表、预览、回收站和批量操作统一为资源管理器式工作台。
5. 邮件/存储页：测试连接、测试发送、默认项和状态切换统一为清晰的操作反馈。

## Later Request-Layer Migration Order

这部分属于基础/优化分支，不属于 Product Design 分支本身：

1. 角色页：权限树、部门树、角色用户列表按 tab/选中项懒加载并缓存。
2. 部门页：部门用户列表只在选择部门后加载，部门树做缓存失效。
3. 配置页：分组和配置项拆分 query key，保存后局部失效。
4. 文件页：分组树、文件列表、回收站、移动/复制目标列表拆分 query key。
5. 邮件/存储页：测试连接、测试发送用 mutation 状态替代局部 loading。

## Acceptance

- 主页面首屏只请求当前页面主数据和必要会话数据。
- 打开表单、下拉、tab 或侧栏时才请求相应辅助数据。
- 增删改后不用整页刷新，按 query key 失效或局部替换。
- 桌面 1440px 和移动 390px 视口下无明显挤压、重叠和按钮文案溢出。
