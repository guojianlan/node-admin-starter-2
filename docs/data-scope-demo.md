# 数据权限演示数据

这套数据用于在本地开发环境验证角色的五种数据范围。执行命令：

```bash
pnpm db:seed:data-scope-demo
```

脚本只允许连接 `localhost`、`127.0.0.1` 或 `::1` 的非生产数据库，可以重复执行，
不会执行 `db:reset`，也不会删除普通业务数据。

## 部门结构

```text
[数据范围] 演示总部
├── [数据范围] 华南中心
│   ├── [数据范围] 深圳研发部
│   └── [数据范围] 广州运营部
└── [数据范围] 华东中心
    └── [数据范围] 上海销售部
```

## 验收账号

所有账号共用本地演示密码 `ScopeDemo123!`。

| 账号                | 角色数据范围   | 账号所在部门 | 在用户管理中预期看到的数据             |
| ------------------- | -------------- | ------------ | -------------------------------------- |
| `scope_demo_all`    | 全部数据       | 华南中心     | 系统全部用户                           |
| `scope_demo_dept`   | 本部门         | 华南中心     | 仅华南中心直属用户，不包含深圳、广州   |
| `scope_demo_tree`   | 本部门及子部门 | 华南中心     | 华南中心、深圳研发部、广州运营部用户   |
| `scope_demo_custom` | 指定部门       | 华南中心     | 仅上海销售部用户                       |
| `scope_demo_self`   | 仅本人         | 深圳研发部   | 只有当前登录账号，不包含同部门样本用户 |

五个角色仅授予仪表盘、个人中心、用户管理查询和部门管理查询权限。这样相同页面中的结果差异
只来自数据范围，而不是不同的功能权限。

## 生效链路

```text
登录用户
  -> sys_user_role 获取角色
  -> sys_role.data_scope 获取范围类型
  -> custom_dept 时读取 sys_role_dept
  -> current_dept_tree 时展开 sys_dept 子部门
  -> resolveDataScopeForUser 生成 deptIds/selfOnly
  -> CRUD Factory 或显式 Route 将条件追加到 SQL
```

当前已接入数据范围的主要验收入口：

- `/system/user` 用户列表。
- `/system/dept` 部门列表和部门用户。
- `/system/role` 中的角色用户列表。

CRUD Factory 会把相同范围用于更新、删除、批量删除、恢复、彻底删除和状态切换。范围外 ID
统一按“记录不存在或无数据权限”处理；批量请求混入一条范围外记录时整批拒绝。声明了
`deptId` / `ownerId` 的模块在创建或修改归属时，也不能提交当前范围外的部门或负责人。

用户重置密码是显式安全接口，不走 CRUD Factory，但同样会先校验目标用户的数据范围。
角色分配属于另一条授权委派策略：数据范围只回答“能看和能操作哪些记录”，不会自动回答
“可以把哪些高权限角色授予别人”。上线部门管理员代管用户前，应再定义可委派角色范围。

超级管理员用户 ID `1` 始终为全部数据，不受角色数据范围限制。
