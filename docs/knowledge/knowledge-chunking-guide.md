# Knowledge 分块模板使用指南

## 如何选择

| 模板         | 适用内容                                 | 默认目标长度 | 默认重叠 |
| ------------ | ---------------------------------------- | -----------: | -------: |
| 自动识别     | 混合文件类型，大多数知识库               |         1600 |      160 |
| 技术文档     | Markdown、项目手册、API 文档、含代码内容 |         1600 |      160 |
| 段落聚合     | 报告、PRD、方案、普通文章                |         1400 |      140 |
| 句子边界     | FAQ、制度、短知识点和客服话术            |          900 |       90 |
| 递归语义边界 | PDF、DOCX、解析后结构不稳定的文本        |         1400 |      140 |
| 固定长度     | 旧索引兼容或对照实验                     |         1200 |      120 |

目标长度是打包上限，不代表系统会在该字符位置强行切断。结构化策略优先在标题、空行、换行和中英文句子标点处结束。超长单段才会继续寻找更细的边界。

重叠用于把前一个分块末尾的语义上下文带到后一个分块。一般设置为目标长度的 8% 到 15%，并且不能超过 35%。重叠太小会损失跨块语义，太大会增加 Embedding 成本并产生重复召回。

## 配置建议

项目文档目录使用“技术文档”模板。制度与 FAQ 可以使用“句子边界”。扫描 PDF 或格式混乱的 Word 文档使用“递归语义边界”。只有需要复现旧算法时才选择“固定长度”。

修改模板、目标长度或重叠后，对来源文档执行重新索引。通过文档的 `chunkerVersion` 和 `chunkConfigJson` 可以确认实际生效策略。正式调优应建立固定问题集，对比 Recall@K、MRR、nDCG、引用覆盖和无依据回答率，而不是只观察分块数量。
