# Admin Base 功能测试用例基线

> 本文档按业务闭环组织测试场景。逐接口契约和逐页面验收分别见 [`admin-base-api-test-cases.md`](admin-base-api-test-cases.md) 与 [`admin-base-page-test-cases.md`](admin-base-page-test-cases.md)；`pnpm test:check-cases` 会校验源码中的所有 API 和 App Router 页面均已登记。

> 最新验收执行记录：[`test-reports/admin-base-acceptance-2026-07-16.md`](test-reports/admin-base-acceptance-2026-07-16.md)。

> 版本：2026-07-31
> 适用分支：`codex/admin-base-migration-plan`
> 适用范围：Admin Base 当前核心框架功能、后台页面、API、权限、安全策略和生产发布能力。

## 1. 文档目标

本文是 Admin Base 的功能测试 source of truth，用于回答以下问题：

- 当前每个功能应该验证什么。
- 哪些用例已经有自动化测试覆盖。
- 哪些用例需要浏览器手工验收。
- 哪些用例必须连接真实 S3、SMTP、OAuth、SMS 或 LLM Provider 才能验收。
- 发布、合并和生产部署前应该执行哪些门禁。

代码实现、权限和接口发生变化时，应在同一个提交中更新本文对应模块。新增后台模块至少补充正常路径、权限失败、参数失败、系统数据保护、操作日志和页面状态用例。

## 2. 用例约定

| 标记 | 含义 |
| --- | --- |
| P0 | 登录、权限、数据安全、核心写入、生产安全等阻断发布的问题 |
| P1 | 主要业务闭环和重要失败路径 |
| P2 | 体验、兼容、空状态和辅助能力 |
| 自动 | 已有 Vitest、Playwright、route check、build 或 smoke 覆盖 |
| 手工 | 当前应由测试人员在浏览器中执行 |
| 环境 | 必须连接真实外部服务或生产同构环境 |
| 待补自动化 | 用例已定义，但尚未形成稳定自动化 |

标准测试身份：

| 身份 | 用途 |
| --- | --- |
| 超级管理员 | 验证全部菜单、写操作、系统数据保护和资源配置 |
| 只读管理员 | 验证只有查询权限时的菜单、按钮和 API 403 |
| 部门管理员 A | 验证本部门、本部门及子部门数据范围 |
| 部门管理员 B | 验证跨部门越权被拒绝 |
| 普通用户 | 验证个人中心、消息中心和无后台权限状态 |
| 强制改密用户 | 验证首次登录、密码过期和管理员重置后的路由限制 |
